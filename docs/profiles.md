# Built-in profiles

A profile is a JSON file listing the checks that apply to one upload target, with their limits.
`svqa profiles` lists them and `svqa profiles show <id>` prints one with its sources. See
[writing-profiles.md](writing-profiles.md) to extend or add your own.

Every rule carries a **basis**, so you can see where a number comes from:

| Basis | Meaning |
| --- | --- |
| `documented` | Stated on the platform's own specification page (linked below). |
| `observed` | Seen in practice by the authors and dated. Not a published rule. Treat it as likely, not guaranteed. |
| `convention` | Widely used good practice that the platform does not require (for example a -14 LUFS loudness target). These rules only warn. |
| `derived` | Follows from a documented rule (for example a codec level implied by a profile). |

Severity decides what fails a run. `error` fails `svqa check` (exit code 1). `warn` is reported but passes, unless you use
`--strict`. `info` is shown for context only. A rule with only `recommended` values never reports above `warn`.

## How the values were chosen, and what is uncertain

Platform specifications change without notice, and the pages are not always precise. Each source below was read on the
date shown. If you find a change, please open a "Platform spec changed" issue with a link.

- **Instagram Graph API (Reels, Stories).** Meta's "IG User Media" reference lists container, codec, frame rate, size,
  bitrate, duration and file-size limits for Reels and Stories. Two points are open to interpretation. "VBR, 25Mbps
  maximum" is checked as the average video bitrate, because Meta does not say over what window. "128kbps" for audio does
  not say whether it is a ceiling or a target, so it is treated as a ceiling with 2 kbps of slack, and only warns. The
  no-B-frames rule is not Meta's; it is a conservative choice that makes "no edit lists" easy to meet.
- **Meta ads on Instagram.** The Ads Guide mostly gives recommendations, so most rules warn. Its listed duration for
  Reels ads is up to 15 minutes; the 15-second limit in this profile is an observation from October 2026 (longer
  videos were not eligible for Instagram ad placements), and is marked `observed`. Because it contradicts the
  documentation, it only warns; `--strict` or your own profile can make it an error. Safe zones for text and logos are
  not checked.
- **App Store app previews.** Apple's "App preview specifications" page gives the accepted resolutions per device, a 15 to 30
  second length, a 500 MB limit, H.264 "up to High Profile Level 4.0" with a 10 to 12 Mbps target and a 30 fps maximum,
  and stereo AAC audio. Apple publishes no minimum frame rate; the 25 fps lower bound is a convention and warns. Many
  developers report that previews without an audio track fail to upload, so `audio.present` is an error marked
  `observed`; `svqa fix` adds a silent track.
- **YouTube Shorts.** Being classified as a Short (square or vertical, up to three minutes) is documented, so those rules
  are errors: a wider or longer upload is not rejected, it just becomes a regular video. The encoding settings come from
  YouTube's "recommended upload encoding settings" and only warn, because YouTube re-encodes every upload. The -14 LUFS
  reference for YouTube's loudness normalisation is widely measured by the community but not documented by YouTube.
- **TikTok.** Limits come from the Content Posting API media transfer guide. Not every account can post videos longer than
  three minutes, so 3 minutes is a warning and 10 minutes (the API maximum) is the error. TikTok documents no audio or
  loudness requirements.

Loudness targets everywhere are conventions: every platform here normalises playback loudness in its own way, and a
consistent master simply makes the result predictable.

- Meta lists the audio bitrate as '128kbps' without saying whether it is a ceiling or a target. This profile treats it as a ceiling (with 2 kbps of slack for AAC overshoot) and only warns.
- Meta asks for 'no edit lists'. An MP4 with B-frames normally needs an edit list to start at time zero, which is why this profile also warns about B-frames.
- Instagram re-encodes every upload. Passing these checks makes rejections and processing errors unlikely; it does not guarantee how the post is ranked.

`svqa fix` target: 1080x1920, H.264 high, CRF 20, max 8000 kbps, AAC 128 kbps 48000 Hz, loudness -14 LUFS.
